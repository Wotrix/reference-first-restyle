# Reference-First Restyle · 先参照，后代码

给 AI 编码代理用的一个 Skill：改界面之前，强制走「参照 → 规格 → 候选 → 实现 → 验收」的顺序。

它治的是一个常见病：AI 写的界面能用，但丑。多数时候不是模型不行，是你没给它参照——「高级一点」「现代一点」「有设计感」这类词在模型那里约等于什么都没说，没有参照时它只能回你训练数据的平均值。

## 它是什么、不是什么

它是一套**流程纪律**，不是审美规则，也不是组件库：

- 不负责告诉你什么是好看的（那是 taste 类 skill 的事）；
- 不提供任何现成代码；
- 只负责保证：没有参照不许动手，没有可执行规格不许写形容词，没有候选方向不许写代码。

和 taste skill 互补：taste 定标准，这个定顺序。单独用也成立——有参照，就有下限。

## 五步分别做什么

**1. 找参照（0 参照不动手）**

触发后第一件事是找参照，按优先级：你手头的截图/设计稿链接最高优先；其次是网上的组件页和图库（页面 URL 加 `.md` 常能拿到 AI 可读的结构化描述，比截图便宜）；最后是你项目里已经长成的同类组件——先对齐既有一致性，再谈新方向。

**2. 蒸馏成规格，不是形容词**

把参照翻译成机器可执行的条目。上面两张卡的差别就是这么来的：

```text
❌ 「更现代一点，有高级感」

✅ 外层圆角 16px、内层 10px
   阴影 0 1px 2px + 0 12px 32px rgba(31,35,40,.09)，带底色色调，不用纯黑
   价格 30px/600，font-variant-numeric: tabular-nums
   强调色只用一个 #0e7c66，只出现在标签与勾选图标上
   徽章不用渐变胶囊，用文字 + 细线
   按钮单一主操作，深墨色填充，次要动作降级为链接
```

规则：规格里出现「高级感」即为不合格——每一条都必须能对应一行具体的 CSS 或一个结构决定。

**3. 候选先行**

一次给 2-3 个方向，每个说清：改了什么、和其他方向差在哪、风险在哪。你选定后才写代码。AI 最大的浪费不是写得慢，而是写完一版你不敢用。

**4. 三约束实现**

- 数据结构与 props 一律不动，只改布局/间距/字号/颜色/圆角/阴影/动效；
- 不引入新依赖，动画用项目已有能力降级实现；
- 出完整单文件，不给 diff。

外部参照只取设计、不取代码——按项目自己的技术栈和数据结构重写。

**5. 验收**

构建通过只是及格线，改完让用户过目。「看起来没问题」不是没问题。

## 安装

把 `SKILL.md` 放进代理的技能目录即可，单文件、无依赖：

```bash
# 项目级（仅当前项目生效）
mkdir -p .agents/skills/reference-first-restyle
curl -fsSL -o .agents/skills/reference-first-restyle/SKILL.md \
  https://raw.githubusercontent.com/Wotrix/reference-first-restyle/main/SKILL.md
```

全局安装则放到 `~/.agents/skills/reference-first-restyle/`。适用于支持 skills 机制的编码代理（ZCode、Claude Code 等）。

## 使用

正常说人话，描述里的触发词会自动匹配：

- 「这个页面太丑了，改观感」→ 会先找参照、给候选，而不是直接动手
- 「照着这张参考图重做这个面板」
- 也可以显式调用 `/reference-first-restyle`
